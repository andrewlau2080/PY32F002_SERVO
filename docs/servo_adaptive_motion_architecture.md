## 1. 目标定义

本项目要实现的是位置闭环舵机控制器：外部 PWM 给出目标位置，电位器给出实际位置，H 桥通过两路方向 PWM 产生正向或反向转矩。控制器应让机构快速但可控地移动，末端平顺减速，利用受控反向输出吸收运动能量，并停在目标附近；静止时按锁力策略保持。

同一算法应能适应电源电压、马达转速/转矩、齿轮箱减速比和机械负载变化。适应的含义是：在线测量当前机构的运动响应，更新速度、起动阈值和制动能力估计，再用统一控制规律计算输出。它不意味着不测电流、不测电压、不标定传感器也能保证任意机构安全；硬件限流、行程校准和传感器质量仍是边界条件。

自适应必须贯穿整个运行过程，而不是一次性出厂学习：快速控制环持续跟踪 PWM 指令并根据实时反馈修正两路输出；并行的慢速辨识环持续比较“给了多少 PWM”与“机构实际产生多少速度/加速度”，在数据可信时更新对象模型和相应 PID/轨迹/制动参数。即使没有新命令，监测、模型健康度判断和 HOLD 稳定性检查也持续运行；出现新指令时立即由快速环执行，不等待慢速辨识。

核心验收目标：

- 目标改变后能及时起动，长行程不过分拖慢。
- 末端制动随当前速度和实测制动能力变化；反向 PWM 用于受控吸能，不把反向满驱动当作刹车。
- 反向制动力在速度接近零时平滑降到零，避免越过目标后再次加速、来回摆动。
- 正反方向都能停准；齿隙、静摩擦和 ADC 噪声不会触发高频反复换向。
- 更换电源、马达、齿轮箱或负载后，控制器能通过受限辨识更新模型；异常情况下退回安全限幅。
- 任何一项曲线结论都能由带时间戳的目标、反馈、速度、两路 PWM、状态和供电数据复核。

### 产品输入与反馈规格

以项目的[舵机规格书](../舵机规格书.pdf) CYS-S3047 第 6 节为准：输入脉宽范围 **500–2500 μs**、中立 **1500 μs**；**1000–2000 μs 对应 90°操作行程**，500–2500 μs 对应约 180°最大行程。500/2500 是最大行程端点，1000/2000 是标称操作行程端点，不能把两组范围混写。

规格书第 1 节的 4.8–6.0 V 是舵机工作电源，不是位置电位器输出电压。当前TSSOP20改线后为PA3/TIM1_CH1 PWM输入、PA4/ADC4电位器反馈；SOP8产品映射另行定义。ADC名义输入范围按板级设计为0–3.3V，对应12bit raw 0–4095。改线前PA3曾记录约0.154–3.195V（raw 189–3929），该历史数据不能代替当前PA4或后续SOP8校准。控制器应分别保存电气量程和机械可用端点，避免把机械端点外推到ADC 0/4095而撞限位。

2026-11-10 更正：实际下载的 V10.5 LCDM 现场路径默认使用 500/1500/2500 μs 映射到 250/1650/3050 mV 的目标坐标；该版通用 `ServoParams` 默认是 900/1500/2100 μs，通用配置宏又是 1000/1500/2000 μs。此前把通用默认值当成 LCDM 现场值不准确。随后未下载的 V10.6 候选将通用默认 PWM 端点改为 500/2500 μs，CRC 有效的已有标定仍保留；通用与 LCDM 的 ADC 端点未统一。实际角度、端点及 1–3 μs 灵敏度仍须实机验证。

## 2. 设计来源与证据边界

本基准整理自：

- `docs/servo_program_design_summary.md`：PWM 位置命令、电位器反馈、H 桥双向输出、参数区和保护。
- `docs/servo_motion_curve_tuning.md`：大误差驱动、接近目标减速、反向刹车、到位 HOLD 分离；并记录单点调参无法解决大过冲。
- `docs/servo_tuning_template_assessment.md`：输入/电位器校准、运动规划、速度估计、锁力、齿隙、堵转、供电/电流观测和型号配置文件。
- `docs/servo_curve_debug_variables.md`：VSG 曲线及状态事件可观察要求。
- `PY32F002_SIGNAL_CAPTURE/CUSTOMER.logicdata`：用户指定的唯一客户波形参考档。

客户档目前已通过现有提取器识别出 Channel 2 的周期边沿片段，可用于研究重复周期和活动区间。当前解析没有可靠解码逻辑电平极性、脉宽、第二条方向通道或 MOS 导通状态。因此，“收尾存在反向 PWM 是为了吸收转动能量”的控制意图来自用户说明；不能把旧笔记中记录的 `930/360/220`、`7/2/3 ms` 等当作该档案独立证明的精确电气波形。旧记录中的这些数值先作为待验证的客户基线，不作为新控制器的硬编码要求。

需要区分三种动作：

1. **滑行**：两路驱动都关闭，电机转子主要靠机械/电气损耗减速。
2. **电气制动**：H 桥将电机端子置于安全的同电位状态，短接产生的反电动势形成制动力；这与反向供电不是同一逻辑。
3. **反向 PWM 吸能**：给与当前速度相反的受限转矩，主动降低速度。占空比必须随速度降低而下降，并在零速附近解除，否则会把刹车变成反向运动命令。

最终 H 桥真值表、死区和安全换向顺序必须以原理图和实际两路引脚测量为准。固件中的“正/反 duty”标签不能代替门极/电机端实测。

## 3. 总体数据流

```text
PWM命令 ─→ 输入有效性/抖动处理 ─→ 位置映射与校准 ─┐
                                                    ├→ 运动目标轨迹 ─→ 自适应运动控制 ─→ 安全输出映射 ─→ 两路PWM/H桥
电位器ADC ─→ 校准/滤波/速度与噪声估计 ───────────┘                         ↑
供电/电流/温度（硬件具备时） ─→ 约束与参数辨识 ─────────────────────────────┘
```

状态、估计器和输出均由同一控制核心维护。LCDM、VSG、SWD 和配置器只读遥测或写入经过验证的参数，不各自实现一套运动控制。

## 4. 控制分层

### A. 输入与位置校准

- 捕获 PWM 脉宽、周期、更新时刻和输入有效性；对 1–3 μs 抖动采用时间/幅度一致性门控。
- 通过低/中/高三点校准，把输入脉宽映射到位置坐标。反向选项分别处理传感器方向和电机方向。
- 目标位置与实际反馈统一使用校准后的有符号位置坐标；原始 ADC 和电压同时保留，便于区分机构运动与电源/地噪声。
- 输入失联、超范围或目标突变异常时由安全层处理，不继续沿用旧速度命令。

### B. 传感器与状态估计

每个固定控制周期更新：

- 位置 `x`：ADC 校准并滤波后的反馈位置。
- 速度 `v`：从带实际时间间隔的 `x` 差分估计；过滤量化噪声但保留制动所需的响应速度。
- 加速度 `a`：从速度变化估计，用于识别当前输出的实际驱动/制动效果。
- 噪声带、静摩擦/起动 duty、方向变化空程：只在输入稳定、输出已知且运行状态合适时更新。
- 模型置信度：样本不足、量化误差大、传感器突跳或电源异常时降低置信度，禁止激进自适应。

所有速度、加速度和模型参数必须使用真实时间差归一化，不能假定 SWD 轮询周期等于控制周期。

### C. 运动轨迹规划

命令改变时锁存运动起点 `x0`、目标 `xt`、方向和初始速度。规划器生成连续的目标位置/目标速度 `xref/vref`，限制最大速度和加速度，避免目标阶跃直接变成 duty 阶跃。

轨迹限值由在线模型和产品安全上限共同决定：

- `vmax`：产品速度上限与当前可达速度估计的较小值。
- `amax`：产品加速上限与当前负载响应估计的较小值。
- `abrake`：当前方向的实测有效减速度下界，并保留安全余量。
- 正反方向分别估计，不能默认机构左右完全对称。

### D. 自适应制动与双路 PWM

令剩余距离 `d = |xt - x|`，沿目标方向的速度为 `v_toward`。制动预测的基础量为：

`d_stop ≈ v_toward² / (2 · abrake)`

工程实现还要加测量/执行延迟距离、PWM 更新延迟和安全余量。进入制动不是固定误差门槛，而是当剩余距离接近预测停车距离时开始降低驱动力。

输出概念：

- 驱动分量推动轨迹跟随，受最大 duty、电流/热约束和 slew 限制。
- 阻尼分量根据速度误差吸收动能；速度越接近目标速度/零速，反向分量越小。
- 只有确认当前速度方向和传感器方向可靠时，才允许反向 PWM；否则先用受限电气制动或滑行。
- 正向 PWM 与反向 PWM 必须互斥，采用明确的换向空档/死区，不能两路重叠导通。
- 到达零速或模型不确定时将反向制动占空比平滑归零；防止制动越过零速后反向加速。
- 两方向输出使用同一套控制定义和独立辨识参数，不能用左右各自任意 PID 常数掩盖映射错误。

建议控制形式是“轨迹前馈 + 位置/速度反馈 + 受限阻尼/吸能”，不预设传统位置 PID 是唯一正确形式。若后续保留 PI/PID，其增益应只是控制器一部分，并由稳定性边界和实测模型约束；积分必须有抗饱和、换向清零/跟踪和 HOLD 隔离。

建议的控制周期状态转换如下。阈值由位置噪声、模型置信度和安全限值生成，不在这里指定新的试验常数：

| 状态 | 主要输出 | 转换条件 |
|---|---|---|
| `IDLE/HOLD` | 噪声带内滑行或限力保持；不保留旧运动积分 | 新目标稳定且超出命令死区后进入 `ACCEL` |
| `ACCEL` | 沿目标方向的前馈驱动 + 速度反馈，带加速度与电流/占空上限 | 预测剩余距离接近停车距离后进入 `DECEL` |
| `DECEL` | 减小同向驱动，保持速度参考连续下降 | 需要的反向制动力非零时进入 `BRAKE`；速度已低且位置在收敛带内进入 `SETTLE` |
| `BRAKE` | 输出与实测速度相反的有限 PWM；随速度误差下降，不采用固定反向时间/固定占空比 | 速度下降到解除阈值立即转 `SETTLE`；位置/速度方向异常则安全降级 |
| `SETTLE` | 速度参考平滑到零；小量纠偏受限，禁止一帧越点就大力反打 | 位置与速度连续稳定达到条件后进 `HOLD`；目标显著变化后重规划 |
| `FAULT/DEGRADED` | 按故障类型 coast 或经验证的受限 brake；禁止自适应继续放大输出 | 传感器/输入/供电恢复并满足重新使能条件后回 `IDLE` |

控制计算使用沿目标方向的坐标 `s = sign(xt-x)`，并把速度投影为 `v_s = s·v`。正值代表正在靠近目标，负值代表远离目标。停车距离估计为：

`d_stop = max(0, v_s)² / (2·a_brake_est) + |v_s|·t_latency + d_margin`

`a_brake_est` 来自已确认的反向输出样本；估计无效时用经硬件验证的保守下界，不能把未知值当成强刹车能力。减速阶段生成连续的 `v_ref`，其变化率不超过安全减速度。反向制动命令只跟踪 `v_ref` 与 `v_s` 的差：

`u_brake = -sign(v) · clamp(Kv·(|v|-v_ref), 0, u_brake_max)`

此式表达结构而非可直接烧录的数值。`Kv`、`u_brake_max`、速度滤波延迟和解除阈值需由日志/受限辨识确定；应有滞回与时间确认，零速解除优先于位置误差纠偏，避免制动输出跨过零速造成反向加速。

反刹模型只在当前输出方向与测得速度可靠、样本时间差有效、ADC 未跳变且没有堵转/电源故障时更新。制动期间用 `a_obs = -sign(v)·Δv/Δt` 估计减速度，并按 duty 归一化；异常加速度、速度符号翻转或反馈不动立即停止该次更新并触发限幅/降级。

### E. 到位、HOLD 与外力锁止

运动停稳判据同时看位置误差、速度和稳定时间，不仅看某一帧进入 ADC 死区。

- 停稳后记录实际位置为 hold anchor，避免目标不变时持续积累积分。
- 静止噪声带内不动作；超过噪声/齿隙阈值后，按受限锁力曲线响应外力。
- HOLD 的锁力输出与运动末端反刹分开调参、分开遥测。
- 外力移开后回到锚点仍使用受限轨迹，不执行瞬时满 duty。

### F. 安全与降级

独立于运动控制器的安全监督负责输入失联、ADC 断线/跳变、堵转、过流、欠压/过压、过温、控制周期超时、模型异常和输出互锁。电流、马达供电电压或温度没有硬件测量时，功能应清楚标记为未实现，不能用 MCU VDD 监控冒充马达电源监控。

安全动作是产品选择的 coast、受控 brake 或锁止，不可一概写成“无信号就刹车”；按机械风险、温升和电流验证后设定。

## 5.4 学习记忆与 Flash 持久化

记忆分两层，避免把“持续学习”变成“每个控制周期都写 Flash”：

| 层 | 保存内容 | 生命周期 |
|---|---|---|
| 在线工作模型（RAM） | 正反向速度响应、起动阈值、时延、制动能力、协方差/置信度、近期残差 | 运行时持续监控和缓慢更新；掉电可丢弃未确认更新 |
| 已确认学习档案（Flash） | 模型估计值、位置校准摘要、应用/机构 ID、固件/格式版本、样本数、测试范围、性能统计（到位误差/过冲/时间）、代次号与 CRC | 模型经过多次动作验证、置信度足够且安全指标合格后，由明确保存动作或配置流程提交；下次上电校验后作为初始参考 |

每次动作的完整高速曲线不适合反复写 MCU Flash。动作原始记录保存在主机/采集文件；Flash 保存可复用的模型和少量统计摘要，后续动作可以拿当前结果与已确认档案作差异比较。每次加载后仍继续在线监控，不把旧模型视为永远正确；发现明显偏差时在 RAM 建立新候选，不能直接覆盖最后一份有效档案。

### 工况适用性与模型复用

Flash 中的学习模型是带适用条件的**候选参考**，不是所有机构/负载都可直接套用的通用 PID。至少要把舵机/马达型号、齿轮箱或产品型号、负载档（空载/规定负载）、PWM—位置校准、PA3 端点校准、H 桥频率/拓扑和可测的供电档记录到模型上下文。静态校准或型号不同，指纹不匹配时直接拒绝该模型。

空载与带载即使使用相同硬件编号，也可能有不同动态响应；若没有负载传感器，固件不能只凭 Flash 标记确定负载是否相同。因此上电只读入为 `UNVERIFIED` 候选，先使用产品安全范围内的保守控制；在离开限位且输入/ADC 健康时，通过低风险短行程比较实测速度、加减速和滑行响应。与旧模型在允许偏差内才逐步融合启用；偏差过大则冻结旧模型权重、重新建立 RAM 候选。没有安全激励条件时保持保守模型，不盲目应用空载或带载档案。

不同工况需要独立的模型 ID/profile ID；保存时只更新当前工况槽。现有两个 128 B 槽承担断电安全的 A/B 更新，不等同于两个工况各自的双槽。如果要同时保留空载和带载模型，必须扩展记录布局或将非活动模板保存在主机/工装；不能让新模型覆盖另一工况唯一有效档案。只有该工况多次动作达到误差/过冲/稳定性门槛且明确确认后，才提交对应档案。

当前 linker 只为参数保留最后一个 128 字节 Flash 页。`ServoParams` 有 55 个 `uint16_t` 字段，连同头/标志/CRC 最少约 122 字节，现有页几乎已满。因此学习模型需采用独立、带版本和 CRC 的记录布局，并重新规划 linker/烧录保护范围；不能直接追加字段而仍假设原页够用。建议参数校准页与学习模型页分开，模型记录采用双槽/代次提交或等效的断电安全策略，启动时选取 CRC、版本、范围均有效且代次最新的记录；任何模型记录无效时安全回退到参数页和保守默认模型。

Flash 擦写有寿命限制，持久化应按“候选模型稳定且值得保存”触发，并加入最小保存间隔、变化门槛、掉电/复位保护和保存计数；禁止按控制周期、PWM 帧或每个动作无条件擦页。具体页数量、槽位大小、擦写寿命和升级保留范围需结合芯片手册与现有固件大小核定后再定版。

## 5. 自适应辨识策略

你的原则确定为控制器的主线：**先给出已知、受限的 PWM 驱动，再观察电位器位置随时间的变化；控制器用这组输入/输出响应识别当前整套马达、驱动、电源、齿轮箱和负载的等效运动特性，然后据此调整 PID/轨迹/制动参数。** 不先猜某个马达应使用多少 PID，也不把一次调机常数当成所有机构的通用值。

辨识对象是“PWM 命令到输出轴速度/位置”的等效闭环对象。它能适应组件变化造成的整体响应变化，但单靠位置反馈不能把电压、绕组、负载转矩和齿轮摩擦分别物理拆解出来。对控制来说通常先估计其合成效果即可；若需要判断过载、堵转与低压的具体原因，仍要增加马达电压/电流测量。

### 5.1 在线对象模型与自整定 PID

在一个方向和局部 duty 范围内，可先辨识离散速度模型：

`v[k+1] = a·v[k] + b·u_eff[k] + c·sign(v[k]) + w[k]`

其中 `u_eff` 是经过 H 桥实际输出层限幅/换向后的有符号 PWM；`a` 表示速度惯性/衰减，`b` 表示 PWM 对速度变化的等效作用，`c` 汇总库仑摩擦/负载偏置，`w` 是扰动与测量误差。正向和反向分别估计；起动死区单独保存，不能让 RLS 把静摩擦区误当线性增益。

- 只有输入有足够变化、时间戳正确、位置/速度可信且未触发限幅/堵转时才更新模型；稳态 HOLD 不具备足够激励，不强行辨识。
- 可用带遗忘因子和投影边界的递归最小二乘（RLS）慢速更新 `a/b/c`；参数变化率、协方差和模型残差用于置信度判定。
- 用辨识模型按固定的目标响应速度/阻尼比计算或查表得到速度环 PID/PI 参数；位置环只生成平滑速度参考。这样变化的是模型对应的控制器参数，而不是直接凭位置误差大小随意放大 PID。
- 把期望响应作为产品配置的行为目标（例如目标响应时间/允许过冲/最大加速度），不是某种马达专属 PID 常数。期望值必须受电流、供电、温升、机械强度和传感器带宽的安全上限约束。
- 反向制动复用辨识出的反方向输出能力和当前速度：控制目标是把速度收敛到零，不是把位置误差简单反号后继续全力追位置。接近零速时制动命令必须退出，再由低速位置环收尾。

运行时按双时间尺度闭环工作：

| 环路 | 持续任务 | 更新约束 |
|---|---|---|
| 快速控制环 | 每个控制周期读取 PWM 命令与位置反馈，更新速度/误差，计算轨迹和两路输出，处理制动、到位、保持及保护 | 由固定控制周期和已验证的时延决定；不能被参数写入、LCDM 或辨识计算阻塞 |
| 慢速自适应环 | 累积实际 PWM 与位置/速度/加速度响应，更新方向模型、摩擦/起动阈值、速度增益和制动能力，再重新计算 PID/轨迹参数 | 仅接纳有效运动样本；参数有变化率限制、置信度门槛和安全投影，输出连续过渡 |
| 监督/诊断环 | 持续看输入新鲜度、ADC噪声、估计残差、输出限幅、堵转/温升/供电状态以及模型是否漂移 | 发现异常立即抑制学习并触发安全策略；恢复后重新确认数据再学习 |

因此“每时每刻监控和修整”具体表现为：**控制输出持续修整，机构模型持续观察并在可靠时更新，PID 参数随模型缓慢重整，异常时冻结自适应并优先保安全。** 不应让每个采样噪声都直接改一次 PID，否则会把噪声和瞬态误当成机构特性。

以输入/速度数据在线估计模型、再重算控制器参数的自整定调节器已有成熟控制方法；本项目采用该类“对象辨识 → 控制器整定”的原则，而不是照搬其它产品未公开的参数或代码。[DC 电机自整定调节器研究](https://ejournal.csol.or.id/index.php/csol/article/view/270) 描述了用在线 RLS 估计电机动态并自动重整离散控制器的路线。

### 5.2 可更新的机构特性

#### 当前代码进度（2026-11-08，V10.5 研发版）

`src/servo_adaptive.c` 已加入第一阶段在线估算：从有效电位器速度与 H 桥当前 duty 估算正反向速度响应，并记录滑行衰减与反向制动减速度；速度增益样本要求 duty 稳定、速度同向且速度变化进入稳定门限，避免把明显加速瞬态当作稳态增益。有效驱动样本数以缓慢变化的置信度参与普通 LCDM 闭环的速度增益和前馈占空比修正。已有 Flash 模型置信度作为下限保留，防止刚上电时因 RAM 样本计数归零而突然降低信任度。修正受基准增益 0.5–2.0 倍边界限制。`tools/live_servo_curve_swd.py` 现将置信度、正反向速度增益、制动估计与驱动样本数写入实时 CSV 和曲线页摘要，便于现场验证估算器是否持续接收有效数据。

当前实现仍是带限幅的指数平均估算，不是上文建议的 RLS；也没有输入激励质量、模型残差/协方差、堵转和供电异常冻结的完整判据。旧的 `customer_profile_direct` 固定波形路径尚未接入模型化制动，因此客户参考时序仍是既有控制分支。Flash 双槽读写骨架已建，但运行时尚未触发保存，且尚无 MCU 实测擦写验证。因而当前代码只能证明模型估算和受限修正已编译接通，不能宣称自适应闭环已完成或稳定性已验证。

默认与 LCDM 现场编译配置都必须保持通过，且映像须小于应用区 20096 字节；版本号未提升前不得把构建物作为新的现场版下载。

V10.5 已通过 Mac→Ubuntu 正式构建路径：默认配置 `text=10808 / data=28 / bss=1908`，LCDM 现场配置 `text=18192 / data=576 / bss=2496`、BIN 18768 B；应用区和链接器栈余量断言通过。基于实际 `servo_adaptive.c` 的主机输入输出向量也通过速度增益、前馈限幅、制动估算和滑行衰减检查。该结果只验证编译与算法局部映射；客户固定时序分支尚未自适应，且没有 V10.5 的硬件/仿真输出采集，所以不能据此宣称控制行为与理论已一致或授权下载。

算法在线识别的是闭环可观察到的机构响应，不是抽象地“自动找出唯一 PID”。每个合格动作/安全辨识片段可更新：

1. **起动阈值**：从小幅、限时输出判断静摩擦/空程阈值；只在允许的校准/正常运动窗口更新。
2. **速度增益**：记录 `Δx / Δt` 与带符号 PWM duty；分方向、分 duty 区估计速度响应。
3. **制动能力**：记录反向/刹车输出前后 `Δv / Δt`，识别当前电压、负载下的有效减速度；用保守分位值而非单个峰值。
4. **滞后与死区**：比较目标变化、输出变化和位置响应时延，估计方向反转死区/齿隙。
5. **环境变化检测**：速度增益长期变化或位置噪声上升时降低置信度、限制 duty，并缓慢重辨识，不骤改控制增益。

### 5.3 首次/更换机构后的受限学习流程

1. 先确认反馈方向、机械软限位和 H 桥方向；未确认前禁止自学习驱动。
2. 只在离软限位有足够距离、PWM 命令稳定、传感器健康时进入识别。使用限流电源和产品允许的 duty/电流/时间/行程上限。
3. 对一个方向给短时、低风险 PWM 激励，逐步增加到反馈速度可靠超过噪声带，记录起动阈值、速度变化、加速度与延迟；出现无响应/反馈异常立即停。
4. 受控解除驱动，测量自然减速；再用更小的反向 PWM 分级测量速度下降，验证零速解除和方向互锁。正反方向独立重复。
5. 以合格样本更新临时模型；让模型预测下一次小行程的速度/刹车点，再执行短行程闭环验证。残差或过冲超界时回退到上一个安全模型。
6. 多次往返覆盖小/中/大行程后，统计到点误差、过冲、到位时间、反向次数和 HOLD 漂移；只有模型稳定且用户/工装确认后才保存参数页。

自学习只允许在运动数据可辨识且安全条件满足时进行。首次建模无法保证任意负载的绝对安全；硬件限流/过流保护与行程防撞必须先存在，学习层不能取代保护层。

更新律须有：样本质量门槛、每次变化上限、物理合理范围、掉电持久化策略和回退模板。在线状态不直接频繁写 Flash；经验证的模型摘要才可由用户/工装确认后保存。

## 6. 关键参数分组

固定安全边界与机构自适应值分开：

| 类别 | 示例 | 来源 |
|---|---|---|
| 产品安全限制 | 最大 duty/电流、最大速度、最大加速度、行程范围、温度边界、换向死区 | 硬件额定值与安全验证，不能在线越界放宽 |

| 机构模型 | 起动 duty、正反速度增益、时延、正反制动减速度、齿隙、摩擦 | 受限在线辨识并带置信度 |
| 控制动态 | 轨迹速度/加速度、末端制动距离、速度阻尼、锁力阈值 | 安全边界内由机构模型计算或慢速自适应 |
| 输入与测量 | PWM 抖动门槛、ADC 噪声、滤波延迟 | 传感器运行统计，变化需保护 |

## 7. 代码架构目标

当前源代码存在两条控制实现：通用 `Servo_Control_Update1ms()`，以及编译 `SERVO_ENABLE_LCDM_RUNTIME_UI_TEST=1` 时在 `app_entry.c` 中运行的 LCDM 专用控制循环。现场构建可能由后者接管主循环。重构第一原则是建立唯一 `ServoController_Update()`，所有构建模式调用同一控制器；UI、测试信号和输入源只能提供标准化输入，不能含有独立 PID/运动状态机。

目标模块边界：

| 模块 | 输入 | 输出/职责 |
|---|---|---|
| `servo_input` | PWM capture / test command | 稳定命令、输入有效性、更新事件 |
| `servo_position` | ADC raw、VDD、校准 | 校准位置、噪声、传感器健康 |
| `servo_estimator` | 位置、实际 dt、输出历史 | 速度、加速度、方向、置信度、机构模型 |
| `servo_trajectory` | 当前位置/速度、目标、模型、安全上限 | 连续参考位置/速度/加速度与阶段 |
| `servo_controller` | 参考轨迹、状态估计、模型 | 带符号转矩请求与制动/保持请求 |
| `hbridge` | 请求、安全许可 | 两路互斥 PWM、制动模式、换向死区 |
| `servo_safety` | 输入/测量/电流/电压/温度/时序 | 输出限制、故障状态和恢复条件 |
| `servo_telemetry` | 所有模块快照 | 可复核 VSG/日志记录，不参与控制决策 |
| `servo_params` | 产品限制/校准/经确认模型 | CRC、版本兼容、默认回退 |

控制循环时钟和电机 PWM 载波时钟分离。20 μs 软件 tick 不具备 50 kHz PWM 的有效调制分辨率；客户文件显示的约 20 μs 重复间隔不能直接写入当前软件 PWM 频率。输出级应由定时器硬件 PWM 或经验证的驱动器接口实现，并对照两路实测引脚时序确认。

## 8. 遥测和验证要求

每个控制周期日志至少记录：

`timestamp, command_us, target_position, feedback_raw, feedback_position, error, velocity, acceleration, reference_position, reference_velocity, drive_forward_duty, drive_reverse_duty, brake_mode, state, phase, model_speed_gain, model_brake_decel, model_confidence, motor_supply_mv, current_ma, fault_flags`

硬件暂时没有电压/电流传感器时字段标为 unavailable，不能造值。事件码至少分开：启动、加速、巡航、预测减速、电气刹车、反向 PWM 吸能、零速解除、HOLD、外力锁止、换向空档、堵转/降级。

客户比较页应只把 `CUSTOMER.logicdata` 作为客户基准；我们的下方数据必须明确是 VSG 推导值还是逻辑分析仪实际引脚值。只有同一台逻辑分析仪同步采到客户参考和我们正反两路引脚，才能比较高低电平、相位、占空比和换向互锁。

验证顺序：

1. 静态验证输入映射、反馈端点、方向和 ADC 噪声。
2. 限流、空载验证 H 桥两方向真值表、互锁、滑行、电气制动、反向 PWM 和零速解除。
3. 在已知机构上做低速短行程，确认位置速度估计与输出符号。
4. 分别做低/中/高目标和正反方向，记录起动、过冲、停车时间、电流/电压、温升和摆动。
5. 改电压、马达、齿轮箱/负载，验证模型缓慢重新识别，并确认安全上限不被突破。
6. 固定参数/模型重复多次，比较停点误差分布和最大过冲，不能只挑一条“看起来好”的曲线。

## 9. 当前代码事实与重构次序

当前代码事实：

- 位置闭环和 VSG 已有；PWM 输入、电位器 ADC、H 桥方向输出与参数 CRC 层已存在。
- `servo_control.c` 有一套 1 ms 通用控制；现场 LCDM 构建启用 `SERVO_ENABLE_LCDM_RUNTIME_UI_TEST=1` 后，会先进入 LCDM 专用无限循环，实际使用 `app_entry.c:lcdm_servo_loop_update_fast()`，不会进入通用 `Servo_Control_Update1ms()` 主循环。两套实现不是同一算法入口。
- 现场闭环中，命令脉宽变化达到 `400 μs` 就启动 `customer_profile_direct`：固定正向 `930 duty / 7 ms`，随后固定反向 `360 / 2 ms`、反向 `220 / 3 ms`，再等待 24 ms coast gate。此阶段不按实测速度/停车距离调节反向输出，也绕过一般闭环的 duty slew、近目标软限幅和方向换向保护。它可以复现预设时序，却不是跨电压/马达/齿轮箱自适应的制动算法。
- 因而应保留客户两路波形所表达的“驱动后用反向输出吸能、逐渐收尾”这一控制意图；重构时把固定毫秒/占空比变成受实际速度和在线制动能力约束的阶段条件。用户确认的波形行为是设计输入，当前单档文件解析仍不能证明精确两路电平和数值。
- `HBridge_Brake()` 当前调用 `HBridge_Coast()`，并没有独立的电气短路制动输出。现场 V10.4 的固定反向 duty 是反向供电吸能路径，不是该 `Brake()` API 的电气刹车。
- 统一入口的工程落点应是 `ServoController_Update(input, sensor, dt, params)`：普通固件和 LCDM 固件都调用它；LCDM 负责按时服务控制器和展示/编辑参数，不能保留自己的控制律。
- 第一阶段代码已建立学习档案存储骨架：新增 `servo_model_store.c/.h`，两个 128B 槽轮换保存、代次选择、CRC 校验；链接脚本预留 384B，参数仍在最后 128B，Ubuntu 下载 BIN 保护尾区同步扩大。两个运行入口均读取档案有效标志 `g_servo_model_record_valid`。当前控制器尚未消费学习参数，也没有自动保存触发；此项只完成存储底座，未完成自适 PID。
- Ubuntu 默认构建与 V10.x LCDM 现场构建均已通过。现场 BIN 为 17300B，小于新的 20096B 应用上限；链接地图确认 `.servo_params` 仍在 `0x08004f80`，应用段未进入保留尾区。为使默认关闭 TJC 的构建可链接，Makefile 现始终编译 TJC 适配文件的空实现，只有启用时才加入 UART HAL。
- 尚未做 Flash 真机读写、断电中断写入、旧参数保留或自动模型载入控制效果验证，也没有下载固件；当前源码不能据此宣称自适 PID 已完成。
- VSG SWD 采样比 1 ms 控制周期慢得多，不适合证明 2–10 ms 阶段和 PWM 载波是否正确。关键阶段需固件环形高速事件日志和外部逻辑分析仪。
- 目前遥测的 VDD 是 MCU/ADC 供电估算，不等于马达电源测量；没有电流传感器就无法可靠识别转矩或区分堵转与高负载。
- 当前 `HBridge_Brake()` 与 `HBridge_Coast()` 仍是同一输出行为；真正刹车模式必须按 H 桥拓扑安全实现并实测。

按以下顺序推进，不先改 PID 数字：

1. 把本文件作为控制设计基准；将客户档可证实内容与历史经验参数分开标注。
2. 整理唯一控制器状态和输出术语，确认客户两路 PWM 及本机 H 桥真值表。
3. 增强高速事件环形日志，外部同步采集客户样机/本机两路输出。
4. 把估计器、轨迹规划、输出控制、安全监督拆分成单一实现；测试模式只替换输入源。
5. 先验证固定保守模型，再启用受限在线辨识；辨识有效后才允许自动更新轨迹和制动能力。
6. 最后评估是否需要 PI/PID 微调；每次改动用相同动作序列、供电条件和重复统计验证。

在以上证据与单一控制路径建立前，不以修改某个 PID 增益、反刹 duty 或固定阶段毫秒数作为本次架构工作的完成标准。
