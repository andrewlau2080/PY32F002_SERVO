# R04 LCDM redraw regression and fix — 2026-11-15

- **Failure reproduction:** R5 force-coast stress image redrew P50 every 250ms. Over 40.078s/159 SWD samples, PWM stayed at 1503us; expected 1503→1506→1503 was not observed. Context nibbles were wait=2, UART=5, touch=0, main=0; cumulative dropped ticks=30 and max backlog=10 were stable throughout. Failure capture: `../r04_ui_redraw_stress_20261115/`.
- **Root cause:** `lcdm_draw_p50()` called `lcdm_reset_pwm_live_cache()` on every page redraw. That function reset controller state and `s_lcdm_runtime_pwm_start_ms`, restarting the internal command sequence before it reached its 30s ramp.
- **Fix:** initialize/reset the PWM and controller cache once during runtime UI startup; retain reset on explicit PWM source changes; remove the reset from the page drawing function. Added guarded R04 stress mode that redraws the diagnostic page every 250ms. This changes page-render side effects, not control gains or bridge drive.
- **After-fix force-coast capture:** 40.127s, 161 samples; PWM sync passed (1503 first, 1506 peak, returned near center). Context nibbles wait=2/UART=5/touch=0/main=0 and dropped/max counters 30/11 remained unchanged during the capture. Sequence consistency 140/161. No H-bridge drive was possible in this image.
- **Readback:** R6 candidate app (18,904B) matched the BIN exactly; full-flash SHA256=`89600fe63b3212efd5eaaf69503f06b06012296aae36e3cceef357b343098826`; tail384 all `FF`; core Running. Afterwards R5 force-coast was restored and verified: full-flash SHA256=`5ad1ea0521c1b03bc99b9a62f9d3b7836a6e2df20299ea90cf21c26bb3a7f51b`.
- This proves the internal command/update sequence continues during a 250ms automatic P50 redraw stress on this diagnostic path. It does not prove sub-millisecond scheduling or physical H-bridge response. R04 remains partial until high-resolution timing and command-to-output latency are measured.
